# C++ 测试用例设计

对被测 C++ 单元做**主动的用例设计**，在编写测试之前/之中系统性地覆盖边界条件、等价类与分支路径。与 `cpp-test-review`（编写完成后的质量审查）互补，形成「先设计、后审查」的闭环。

## 适用范围

- **被测对象**：C++ 类、函数、模板、状态机等单元（被测源码为 `.h`/`.hpp`/`.cpp`/`.cc`）
- **使用时机**：新增测试文件、为已有测试补充用例、重构后重估覆盖、需求变更引入新边界时
- **测试框架**：gtest、Catch2、doctest、Boost.Test 等（本技能聚焦用例设计，框架无关）
- **不适用**：生产代码编码规范（由 `cpp-rules` 负责）；测试代码质量审查（由 `cpp-test-review` 负责）；模块架构审查（由 `cpp-arch-review` 负责）

## 工作流程

1. **识别被测单元**：确定被测函数/类，列出全部输入维度（参数、全局状态、环境）与输出空间
2. **输入空间分析**：对每个输入维度划分有效/无效范围，标记边界点（BVA）与等价类（ECP）
3. **设计用例**：按 BVA/ECP/BRP 生成用例清单，每条标注覆盖的规则编号
4. **结构化组织**：用参数化集中管理边界用例、规范命名（OGN）
5. **自查与报告**：输出用例矩阵并标注未覆盖项，作为 `cpp-test-review` 审查时的核对输入

## 严重级别

| 级别    | 含义                                          |
| ------- | --------------------------------------------- |
| blocker | 必须设计到位，缺失将导致边界/覆盖盲区未被测试 |
| warning | 建议项，改善可维护性与可读性，不阻塞          |

## Blocker 检查清单

### BVA：边界值分析

- **BVA-001**：每个数值型参数/返回值必须覆盖边界两侧邻域。以接口文档的合法边界 B 为基准，覆盖 `B-1`、`B`、`B+1`（无符号类型取 `0` 与最大值邻域）；边界的包含/排斥语义以接口声明为准。禁止仅用典型中间值测试
  > 例：`int bytesToMbps(int bytes)` → 测 `0`、`1`、`INT_MAX-1`、`INT_MAX`；`int div(int a, int b)` 额外测 `b = ±1`、结果恰好不溢出/恰好溢出的组合。缓冲区上限 `maxSize` → 测 `maxSize-1`、`maxSize`、`maxSize+1`，确认「等于上限可用、超上限拒绝」。
- **BVA-002**：容器/序列边界——空、单元素、满容量、恰好容量上限、超容量输入各需独立用例，禁止只测「若干一般元素」
  > 如 `std::vector` 从 0→1、`capacity()` 恰好分配上限、`pop_back` 至空后再访问、扩容翻倍处的拷贝/移动语义。
- **BVA-003**：字符串边界——空串、单字符、恰好等于缓冲上限（注意 NUL 终止符占位）、超出上限、含内嵌 `\0`、多字节 UTF-8 截断处。`snprintf`/`strncpy` 类接口必须测「长度等于缓冲区大小」与「大小-1」两侧
- **BVA-004**：浮点边界——`0.0`、`-0.0`、±∞、NaN、最小正规格化数/次正规数、`epsilon` 邻域；整数恰在浮点精确表示边界内外的值（如大 `int64` 转 `double` 的精度损失）
- **BVA-005**：索引/迭代边界——`0`、`size()-1`、`size()`（越界首个）、负数（有符号索引越界）、迭代器首/末/末+1。与 `cpp-rules` 的 SEC-A002（越界）与 SEC-B001（符号混合）约束相呼应
- **BVA-006**：时间/计数边界——0 时间片、恰在超时阈值两侧（T 与 T±1ms 级）、重试上限 N 与 N+1、节流计数 0/1/N。测试侧用 fake clock 推进，见 `cpp-test-review` 的 DET-002
- **BVA-007**：状态转移边界——状态机每个状态的首/末合法动作、每条迁移的两端状态、未注册迁移（非法转移）必须确认被拒绝

### ECP：等价类划分

- **ECP-001**：每个输入维度必须划分「有效等价类」+「至少一个无效等价类」，每个等价类至少一个用例。禁止用例只覆盖正常一类
  > 无效等价类：类型合法但语义非法——空、越界、负值、已关闭句柄、重复注册、并发写入等。无效等价类是边界之外的第二大覆盖盲区。
- **ECP-002**：每个有效等价类必须覆盖类内极值（最小值与最大值），不能只挑「中间舒服值」；与 BVA-001 的 B±1 互补
- **ECP-003**：枚举/离散类型——每个枚举值至少一个用例（含 sentinel：`kInvalid`、`kUnknown`、`kMax`）；位掩码/flag 组合覆盖 `0`、单个 flag、多个 flag 组合、全置位
- **ECP-004**：多个独立输入维度必须做交叉组合——每个无效等价类 × 至少一个有效等价类同时出现。禁止只单独测各维度
  > 多数 bug 藏在「两个维度单独合法、组合后非法」的交叉处；组合爆炸时可用 pairwise 缩减，但每个非法维度必须与一个合法维度组合出现。
- **ECP-005**：有序范围参数（百分比 0–100、角度 0–360、buffer size 1–MAX）必须测「范围外一个值」（负/超上界），确认拒绝行为及错误码/异常与越界方式匹配

### BRP：分支/路径覆盖

- **BRP-001**：被测函数每个分支——`if/else`、`switch` 每个 case 与 `default`、三元、`&&`/`||` 短路两侧、`?:`——都必须有至少一个用例分别命中真/假两翼
- **BRP-002**：循环覆盖 `0` 次（不进入）、`1` 次、`N` 次（N>1）、恰好到循环条件翻转的退出点；禁止只测「正常跑完 N 次」
- **BRP-003**：异常路径——覆盖触发异常的输入组合、异常抛出后的资源释放（RAII 析构顺序）、异常安全保证等级（basic/strong/noexcept）断言；`cpp-rules` ERR-002 声明为 `noexcept` 的函数路径用 `EXPECT_NO_THROW` 显式验证
- **BRP-004**：空值路径——`nullptr`、`std::nullopt`、空 `span`、空 `string_view`、空容器作为输入必须独立用例。空输入与非空内容是两条不同路径
- **BRP-005**：early-return / guard clause（`if (!valid) return;`）每个提前返回分支都要有对应用例；守卫子句难以覆盖时通常是 `cpp-rules` CPLX-004 所述的重构信号

## Warning 检查清单

### OGN：用例组织（warning）

- **OGN-001**：边界/覆盖用例用参数化集中管理——gtest `INSTANTIATE_TEST_SUITE_P`、Catch2 `GENERATE`、doctest 子用例——避免复制粘贴 N 个几乎相同的 `TEST`；参数化使覆盖矩阵可读、可增删
- **OGN-002**：测试命名表达「场景-边界」语义（`ReturnsZero_WhenQueueEmpty`、`DivByZero_Throws`、`ExactCapacity_Ok`），使覆盖矩阵在测试列表即可审查
- **OGN-003**：设计完每个被测单元后回填「未覆盖项」，在测试中显式留 `TODO` 或注释说明原因，禁止悄悄放弃边界用例

## 与其他技能协同

- `cpp-rules`：生产代码规范。测试代码不适用其规则；本技能引用的 SEC-A002（越界）、SEC-B001（符号混合）、CPLX-004（重构信号）、ERR-002（noexcept）仅作为设计导向
- `cpp-test-review`：本技能产出的「用例矩阵 + 未覆盖项」是其审查时的核对输入，重点核对 BVA/BRP 是否真实落地
- 设计中发现被测单元边界过多（有效等价类 >15 个）通常是接口职责过重，优先建议重构而非堆砌用例

## 豁免

- 集成测试（跨模块/端到端）：边界分析聚焦模块接口处，模块内部细节可放宽
- 性能基准测试（`*_bench.cpp`）：不适用本技能
- 与大型遗留测试集集成时，OGN-001/OGN-002（参数化/命名）可分期实施，新建用例必须遵守
- 其余规则无一例外
