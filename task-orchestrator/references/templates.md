# 模板

复制后替换 `<...>`。所有路径用绝对路径。**每类派发的 prompt 都以 SCOPE 块开头。**

## 1. SCOPE.md

写在 `.tmp_research/<task-slug>/SCOPE.md`；之后每次派发逐字嵌入 prompt。

```markdown
# SCOPE（v1）

## 目标
<用户目标原文，不改写。若原话含糊，先追问，别自行改写。>

## 约束
- 不可违反：<不 push / 不改 <目录> / 不动生产配置 / 预算上限 ...>
- 允许：<可新建的文件 / 可运行的命令>

## 输入
- 对象：<文件绝对路径 / URL / 粘贴文本>
- 规则与依据：
  - <技能目录>/code-rules/SKILL.md
  - <若涉及某语言>/code-rules/references/<lang>.md

## 验收标准
| # | 标准 | 判定方式 |
|---|---|---|
| 1 | <可判定陈述> | <命令 + 期望输出/退出码> |
| 2 | <可判定陈述> | <人工检查项，写明看什么> |

## 术语与约定
- <项目内命名、口径、版本>

## 变更记录
- v1：初始
```

## 2. STATE.md

- 档位：S / M / L

- 外部技能调用：plan-review ×<n>（上限 2 轮 / 每轮最坏 10 次派发）、git-commit ×<n>（上限 3 次额外派发）

## 目标（与 SCOPE 一致，防漂移）
<一行>

## 已确认事实
- <事实> —— 证据：<文件:行 / 命令输出 / URL>

## 决策与理由
- 采用：<方案> —— 理由：<...>
- 否掉：<方案> —— 理由：<...>

## 派发台账（预算按此计算）
| # | 阶段 | 用途 | agent 类型 | 结果 |
|---|---|---|---|---|
| 1 | 1 | 调研 A | general-purpose | 完成 |

## 验收记录
| 标准 | 原判 | 复核裁定 | 证据 |

| 1 | PASS | 确认 | `<命令>` → 退出码 0 |

## 3. 派发 prompt 骨架 A — 调研

```text
<SCOPE 块逐字>

## 你的任务
<一句话目标>

## 输出格式（JSON）
字段：结论 / 证据 / 来源 / 未获取项 / 我看到了但没写进来的关键点
- 结论必须可证伪。
- 每条证据给 URL 或绝对路径（含文件:行）、来源类型、发布日期。
- 拿不到就说「未能获取：<目标> — <原因>」，不要猜。
- 配额提示：摘要总量 ≤800 字（提示，非机械校验）。

## 可用工具与信息源
- 可读：<路径列表>
- 可用网络：<https://... 或 fetch-page 脚本路径>
- 不要访问：<...>

## 边界（禁止项）
- 不得修改任何被 Git 跟踪的文件（报告除外）
- 不得派发子 agent
- 不得执行会改变状态的命令
- **不得在返回前自行筛掉半信半疑的发现**：拿不准也报上来，由下游判断

## 完成标准
<SCOPE 中对应的第 N 条验收标准>

## 产出交付方式（必须遵守）
1. 完整产出写入：<绝对路径>.md（目录不存在则创建）
2. 最终回复只给：结论摘要、必须保留的片段、未获取项、我看到了但没写进来的关键点、文件路径
3. 不要复述文件全文
4. 不要读取或粘贴任何子 agent 的 transcript 文件
```

## 4. 派发 prompt 骨架 B — 执行单元（可写）

```text
<SCOPE 块逐字>

## 你的任务
<一句话目标>

## 变更范围
- 只允许改动：<路径列表>
- 禁止改动：<路径列表 / 配置文件 / 其它模块>

## 可用工具与信息源
- 可读：<范围内外的源码、调用方、测试路径>
- 可运行：<该单元允许执行的构建/测试命令>
- 不要访问：<...>

## 输出格式
最终回复给出：改了什么（文件:行）、为什么、验证命令与输出、未决项。
完整报告写入 <绝对路径>.md。

## 边界（禁止项）
- 不得改动「变更范围」之外的文件
- 不得提交（不执行 git add / git commit）
- 不得推送
- 不得派发子 agent
- 不要求你验收自己的产物（后续由独立验收员负责）

## 完成标准
<SCOPE 中对应的第 N 条验收标准>
<必须能在该 worktree 内跑通的命令>

## 交付
1. 完整报告写入：<绝对路径>.md
2. 最终回复只给：变更清单、验证命令与输出、未决项、报告路径
3. 不要复述报告全文
```

## 5. 派发 prompt 骨架 C — 验收（黑盒）

```text
<SCOPE 块逐字>

## 你的任务
验收下列产物是否满足 SCOPE 中的验收标准。

## 产物
- <绝对路径列表>

## 你能看到的
只有产物、SCOPE 的验收标准、可执行命令。**没有**实现过程、没有执行者的说明。
不要询问背景，自行从产物与命令里取证。

## 可用工具与信息源
- 可读：<产物绝对路径列表>
- 可运行：<验收命令>
- 不要访问：<...>

## 要求（即本步的验收标准）
1. 对每条标准给出四态之一：PASS / PARTIAL / FAIL / UNVERIFIED。
2. 每条结论必须附证据原件：命令 + 输出 + 退出码（或文件:行）。
3. 不确定时倾向 FAIL / PARTIAL，不要倾向 PASS。
4. 必须覆盖反面用例：给出一个应当失败的输入，确认它确实失败。
5. 只测通过路径、未测反面用例的，不得判 PASS。

## 输出格式
| 标准# | 结论 | 证据（命令+输出+退出码） | 理由 |

最后一行：`OVERALL: PASS | PARTIAL | FAIL | UNVERIFIED`

## 边界
- 只读：不得修改任何被跟踪文件
- 不得派发子 agent
- 不得修改产物来「修好」它
- 不要返回摘要式结论而不给证据
```

## 6. 派发 prompt 骨架 D — skeptic（L 档 / 高风险）

```text
<SCOPE 块逐字>

## 你的任务
下面是验收员判为 PASS 的条目。你的任务是**驳倒**它们。

## 待驳条目
- 标准 1：<原判结论 + 证据>
- 标准 2：...

## 可用工具与信息源
- 可读：<产物绝对路径 / 源码路径>
- 可运行：<验收用的命令，与验收员同一套>
- 不要访问：<...>

## 方法
对每条：
1. 自己重跑证据命令（不要相信转述的输出）。
2. 构造当前证据覆盖不到的输入 / 边界，看是否仍满足。
3. 查找反例：产物在什么条件下会不满足该标准。

## 边界（禁止项）
- 只读：不得修改任何被跟踪文件
- 不得派发子 agent
- 不得修改产物来「修好」它
- 不要凭感觉给结论：没有可执行反证就必须写「未能驳倒」

## 完成标准
每条 PASS 都有明确的「驳倒 / 未能驳倒」结论，且附可复现的命令与输出。

## 输出
| 标准# | 是否驳倒 | 反证（命令+输出 / 文件:行） | 结论 |

最后一行：`OVERALL: 全部未能驳倒 | 驳倒 <n> 条`
```

## 7. 汇总 prompt 骨架（L 档且已验证条目 > 15）

```text
<SCOPE 块逐字>

下面是已通过验收（含复核后保留）的条目，编号 [0]-[N]。

## 条目
[0] <位置> — <一句话> — 证据：<...>
...

## 任务
只返回**索引与合并关系**，不要重述正文：
- 同一根因的条目合并：保留一个 index，其余放进 merge。
- 按严重度排序，正确性优先于清理类。
- 最多保留 K 条，K = <由主上下文按 SCOPE 严重度定义填写，默认 15>；超出时在输出中列出被省略的 index 及原因。
- 不要自创编号。

## 可用工具与信息源
- 只依据本 prompt 里给出的条目与证据；不要自行去读产物或源码补充判断。

## 边界（禁止项）
- 不得因为「看起来不重要」而省略条目：省略必须给理由，并进入报告的「被丢弃项」。
- 不得重新裁决条目（不改 verdict、不新增条目）——裁决已由验收与复核完成。
- 不得修改任何文件。

## 完成标准
每个条目要么出现在 decisions，要么出现在 omitted（附理由）；两者总数等于输入条目数。

## 输出格式
{ "decisions": [ { "index": 0, "merge": [3, 7] }, ... ], "omitted": [ { "index": 9, "reason": "..." } ], "summary": "<2-3 句>" }
```
