# 科研文档与汇报材料

## 0. 先定验收标准

本 skill 服务的是**说服型材料**：读者要据此做决定——给不给钱、录不录用、信不信、批不批。
判据是**读者能否形成正确判断**，不是材料的准确度；准确只是底线。

**观感价值与实用价值并列。** 汇报材料的价值不只来自「准确、可追溯、真有人用」，
也来自「让观者（尤其非技术的决策者）形成『这有价值』的判断」。后者不是虚功。

但两者的红线不同：实用价值以**可核对的使用证据**为准，观感价值以**可核对的诚实**为准——
可以说「已确认 8 条、待确认 3 条」，不能说「全部已验证」。
**「能准确说出自己哪一处没闭合」本身就是观感价值的一部分。**

**优先级：**

```
① 一句话结论明确  >  ② 取舍正确（该删的删了）  >  ③ 可读性  >  ④ 视觉  >  ⑤ 完整
```

**底线（不可违反）**：不得编造具体数据、文献、DOI、实验结果、日期、人名。
**非要求（模型常误判为要求）**：不得遗漏细节、每条主张必须加限定语。

> 分清两件事：**允许合理概括**（「参数量降低约一个数量级」不需来源）／**禁止编造具体**
> （「准确率提升 12.3%」没数据就不能写）。混淆这两者，模型就会选择「把所有话都说一遍再到处
> 加限定」——机械化正是这么来的。**规则越像配额，产出越像模板。**

⚠️ **例外**：专利、软著不适用上述排序。**专利**的取舍方向相反：穷尽保护范围优先于可读性。
**软著**更特殊：它是形式登记，不是写作——按 `references/copyright.md` 的材料清单核对即可，
本节的说服型判据基本不适用。

## 1. 开工前：大改先交骨架

成本差一个数量级：**改标题级比改正文级便宜十倍**。骨架没定就写正文＝返工。

- PPT：只写标题（幽灵稿），签字后再写正文
- 申请书：先交「目标—内容—指标」三行
- 论文：先交引言的问题—空白—贡献三段
- 专利：先交独权的必要技术特征清单

## 2. 路由

| 要写的东西 | reference | 读者要做的动作 |
|---|---|---|
| 立项申请书、任务书、开结题报告、中期检查 | `references/proposal.md` | 决定给不给钱 / 过不过 |
| 学术论文（期刊 / 会议） | `references/paper.md` | 决定录不录用 |
| 汇报 PPT | `references/slides.md` | 现场听取结论、判断可信度 |
| HTML 汇报页、md/html 同版放映件 | `references/html-report.md` | 自行浏览、事后回看 |
| 专利（申请文件全文自撰） | `references/patent.md` | 审查新颖性与保护范围 |
| 软著登记材料 | `references/copyright.md` | 形式核验 |
| **任何体裁的成稿，措辞过一遍** | `references/wording.md` | —— 横切层，不改体裁判据 |

**症状入口**：分不清属于哪一类时，按症状走——

- 「写出来像 AI / 太机械 / 像规格说明书」→ 先 `wording.md`，再回到对应体裁
- 「领导/评委觉得没重点」→ `slides.md` §1 的纵向逻辑与标题三类失败
- 「排版难看、溢出、挤」→ `slides.md` §3 版式形状
- 「不知道要交哪些材料」→ 对应体裁的骨架章节

**限定交叉面**：reference 之间默认不交叉，因为每次都多读一份是净损失。
允许的交叉只有两种：**体裁 reference → `wording.md`**（定稿前清扫，单向）、
以及同一项目中多体裁并存时共享 §3 的跨体裁不变量（如立项书与 PPT 同项目，数字与口径同源）。
体裁 reference 之间**不互指**——某条规则如果两个体裁都要，它应当上提到 §3，而不是靠指针串联。

## 3. 跨体裁不变量

**受众必须带判据。**「给领导看」不可判定。样例：「领导听不懂的术语不上屏；能听懂的普通技术词
正常用，第一次出现用一句业务话带过；没被问到就不讲实现细节。」

**信息按读者可见性分层。** 精确度不是被删除，是被**分配到不同层**：

| 层 | 放什么 | PPT 体裁里的叫法 |
|---|---|---|
| 可见层 | 结论、数字、业务词，宁少勿多 | 上屏 |
| 口头层 | 过程、细节、术语解释 | 口播 |
| 内部层 | 技术名、脚本名、口径讨论、弃用数字 | 内部（任何人不得外发） |

申报书＝正文／答辩准备／内部底稿；论文＝正文／附录／内部。
分层的意义是**给「追求精确」的倾向一个安放处**，不让它和「讲清重点」抢同一块版面。

**禁止的是「内容配额」，不是版式密度。** 这条界线必须分清，否则两条规则会互相抵消：

| | 禁 | 可以 |
|---|---|---|
| **内容配额** | 「每页写 3 个结论数字」「全文术语 ≤1 次」「正文 200 字」——**规定了必须写/不许写多少内容** | —— |
| **版式密度** | —— | 「每页一个论点」「一页最多一句结论句」「信息单元 ≤4」「单列表 ≤4 项」「字号种数 ≤6」——**规定同样的内容怎么承载**；违规动作是**拆页 / 重排**，不是删内容 |

**判据**：这条数字约束的是**内容的数量**，还是**排得下排不下**？
内容配额会逼出等长等重的对称结构（机器味的来源之一）；版式密度只是排版参数。

**边界情形要看处置动作**：标题 ≤22 字既有版式面（放得下）也有内容面（多出的字往往是修饰词）。
**处置方式是「先删修饰词、不要缩字号」——这就有内容成分**，属灰区：
该阈值按项目模板实测得出，须在项目规范里写明，不要当作跨项目通则。

**以内容配额换来的整齐，是拿信息换对称。** 要直接点名**形态**：

- 「不是 X，而是 Y」对仗句通篇复用
- 只为凑整齐的「第一、第二、第三」
- 填空式解释（「是什么／为什么需要／没有会怎样」三问三答）
- 固定骨架反复套（「做成了什么／带来什么／证明了什么」「从 X 到 Y」）
- **冒号揭底**：「逻辑很清晰：先建索引」「问题很直接：太慢了」——形容词＋冒号替读者下判断
- 同一种开头或收尾重复（「这一页是……」「一句话：……」）
- 排比、口号式堆叠

> 三个概念的区分：**内容配额**（禁，见上）；**版式密度**（可，见体裁 reference——
> 含「每页一个论点」这类结构上限，违规动作同样是拆页）；
> **诊断阈值**（`wording.md` 的「多少个词算多」，只用于成稿后判定，不用于生成）。

**规则要配清扫动作。** 禁令写进生成提示词作用有限——模型会换下一个差一档的习惯。
定稿前必须**单独扫一遍**并逐条拆掉。（实证：有项目在写作规则里明令禁止机械句式，
文案稿里仍留着骨架句，要靠一次专门清扫才落到产物——禁令本身不会自动生效。）

**原文与映射分离。** 引用规定只用带页码／条款号的原文；自己的推断单独标为【映射】，
不得把推断说成规定。

**唯一事实源 + 弃用口径登记。** 每个数字只有一个出处，改动从源头顺流改到下游。
被推翻的口径登记为「弃用」并在所有对外材料中禁现——否则它会回流。

**区分文献结论与项目经验。** 规则来自公开研究、来自本项目实践、还是只是听起来合理，
要分开标。没有出处的经验法则照样可以用，**但不能声称有依据**——被追问时站不住。

**边界要如实说，不靠话术遮。** 未取得的文号、未接入的功能、未验证的能力，写「待发布／
待接入／待验证」，不写「已形成机制／正在推进」。**能准确说出自己哪一处没闭合，比声称全部闭合
更可信**——被现场证伪一处，损失远大于承认一个边界。

## 4. 格式与产物

字号、色板、母版、版式一律**来自项目规范或官方模板**。本 skill 只规定形状
（三带结构、字号阶梯比例、对齐线数量）和格式来源的优先级：

**官方模板文件 → 项目写明的格式说明 → 无规范时的保守兜底（须标明是兜底）。**

**篇幅上限（页数、正文字数、标题长度、页脚字数）属项目级**——不同场合差别太大，
由项目规范给出；本 skill 只给形状约束，不预设数值上限。

- **有模板时走模板保真**：解包 → 改 XML → 重新打包，不从零排版。正式评审场合格式错直接扣分。
- **有意偏离项目格式，在产物或规则文件里写明理由**。
- **渲染后必须回看产物**（缩略图网格／截图／导出 PDF），肉眼查溢出、密度失衡、标题折行。
  不看产物的「美观」要求等于没有要求。

## 5. 审查

**执行者不验收自己的产物**：同上下文的自我复核只算编辑，不算验收；未独立验收的必须在交付里声明。
验收要有**证据原件**（命令＋输出＋退出码），拿不到证据就记「未能判定」，不能当成通过。

**审查必须在全新上下文中执行。** 做不到时**必须声明「这不是审查」，不得降级冒充**——
同上下文自审的判别力显著下降，且审查者会偏向自己刚写的东西。

目前**只有 `slides.md` §4 给了完整审查协议**（四档 + 证据状态 + `protects`）。
其余体裁按下面三样做最小审查：

| 要素 | 要求 |
|---|---|
| **严重级** | 必修／建议改／明确不改／待确认，四档缺一不可 |
| **证据状态** | 实测（坐标／命令输出）／线索（推断、按公式估）／推测。**线索最高只能到建议改** |
| **protects** | 仅「必修」需要：它保护哪条官方条款、验收标准或用户场景。写不出的降为建议改 |

「明确不改」必须分类给出理由，**不能只说「还差什么」**——只会挑毛病的审查不可用。
四个子类各有各的理由要求：

| 子类 | 须给出 |
|---|---|
| **已证伪** | 复测方法（命令／参数／坐标）＋若按原报告改会怎样 |
| **成立但收益不抵成本** | 收益／风险比较 ＋ Revisit if（什么条件下应改） |
| **纯口味** | 标明「无判据，不构成审查意见」，**不计入结论** |
| **超出范围** | 指出归属范围 |

**未执行 ≠ 没发现问题。** 审查者超时、抓不到文件、工具失败，状态记 `not run`，**绝不能算作零发现**。
裁决时报两个数：`surface pass = 通过／已执行`、`effective pass = 通过／(已执行 − 受阻)`。
这是 PARTIAL 被悄悄算成 PASS 的唯一入口。**报告结尾固定写「本轮未覆盖什么」。**
