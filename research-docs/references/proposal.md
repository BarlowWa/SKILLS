# 立项申请书 / 任务书 / 开结题报告

评估方读它是为了**决定给不给钱、过不过验收**。与会汇报同源，但读者会逐字审阅，且会对照承诺核对结果。

## 1. 先回答的问题

动笔前必须问清（问不满四项就先问，不要臆造）：

1. **评估方是谁**——技术专家、管理方、还是财务？决定技术细节的深度。
2. **本次要促成什么决定**——立项、续拨、结题通过、评优？
3. **一句话主张**——这次申请/验收最该被记住的一件事。
4. **哪些内容明确不讲**——项目边界。**边界不清是申请书最常见的失分点**，
   写进来的东西会被当成承诺。

## 2. 骨架与每节的失败模式

| 节 | 要回答什么 | 失败模式 |
|---|---|---|
| 研究目标 | 做完之后世界有什么不同 | 写成「做 XX 系统」——那是手段不是目标 |
| 研究内容 | 分成几块、各自做什么 | 与目标不对齐；块之间重叠 |
| 技术路线 | 怎么做、为什么这么做 | 只画流程图不讲为什么选它；**关键取舍不写理由** |
| 关键问题/创新点 | 难在哪、你凭什么能做 | 创新点写成形容词；与自己项目内的其它工作重复 |
| 考核指标 | 怎么算做成了 | **不可测量、不可核对**；或用「显著提升」这类词 |
| 进度安排 | 里程碑与时间 | 时间平铺平均分配，不体现关键路径 |
| 基础与条件 | 你已有的人力、数据、平台 | 堆履历，不与本任务需求对应 |
| 风险与对策 | 哪儿可能出问题 | 只写「风险可控」，不说怎么控 |

## 3. 判据

**目标与指标必须可测、可核对。** 「提升某类数据的可用性」是目标，
「13 张核心表的字段可用率由 39.8% 提升至 ≥95%」是指标——两句话的区别在于**后一句能被人复算**。
指标要写清**分母、口径、时间窗**，并准备好复算方式——评审最容易追问的就是「这个数怎么来的」。

**创新点要能指向可核对的事实**，不是形容词。
「国内领先」这类表述在没有对标数据时必须删掉；有对标就写清「相对谁、在什么条件下、差别多少」。

**技术路线要写取舍。** 列出被否掉的方案及否掉的理由，比只写选中的方案有说服力得多——
评审的判断依据往往是「你有没有考虑过别的路」。

**考核指标与进度要对得上。** 每条指标指明在哪个月末、由哪个里程碑产出证据。

**写进去的都是承诺。** 报告中允许「持续优化」的表述，在申请书里就是未完成的指标。
拿不准能不能做到的，写进「研究边界」而不是「研究内容」。

## 4. 结题 / 中期报告的额外规则

**三条对比，缺一不可：**

1. 目标 vs 实际（说清达成与否）
2. 实施前 vs 实施后
3. 原来认定的症结 vs 现在的状态

**如实写边界**（写法见 SKILL.md §3「边界要如实说」）：未取得的批准文号、未接入的功能、
未验证的能力，一律标状态，不用「已形成机制」「正在推进」含糊过关。

**效益只写能核对的。** 时间、次数、覆盖率的对比可以写；金额需要业务参数，拿不出来就不算，
不推算、不类推、不年化。

**与立项承诺逐条对照。** 结题材料的第一张表应该是「申报时的指标 → 现在的实际值 → 达成情况」。
评审会拿申请书对照，主动给这张表比被问出来好。

## 5. 交付前自检

- [ ] 每一条考核指标都能说出「分母、口径、时间窗、怎么复算」？
- [ ] 技术路线里至少写了两条被否掉的备选及理由？
- [ ] 研究内容是否都能追溯到某个目标？有没有目标没有内容支撑？
- [ ] 有没有把实现手段（建个系统/平台）写成了目标本身？
- [ ] 未达成的项是否如实标注了状态，而不是用「持续优化」掩盖？
- [ ] 结题材料是否含「承诺 vs 实际」对照表？
