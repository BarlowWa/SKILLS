# 专利（申请文件全文自撰）

自行撰写全文时，产出是**权利要求书 + 说明书 + 说明书摘要**（可含附图），不止技术交底书。

## 0. 与说服型材料的根本差异

本 skill §0 的优先级排序（结论先行、该删就删）**在专利上不适用**。

| | 汇报材料 | 专利 |
|---|---|---|
| 目标 | 读者快速形成判断 | **穷尽并锁定保护范围**，同时经得起审查 |
| 取舍方向 | 删 | **留**（上位概念、替代方案、变体都要写） |
| 读者 | 业务领导 | 审查员、竞争对手、无效宣告请求人 |
| 失败形态 | 没人记住 | 权利要求被驳回、或写得过窄被人绕开 |

## 1. 文件顺序

1. **权利要求书**：独立权利要求（必要技术特征的最小集合）＋从属权利要求（逐层细化）
2. **说明书**：技术领域 → 背景技术 → 发明内容 → 附图说明 → 具体实施方式
3. **摘要**：一段，指向一幅附图
4. **附图**：标记编号与说明书正文严格对应

## 2. 权利要求

**独立权利要求：必要技术特征要「恰好」。**

- 写进去的特征都是限定，多写一个就窄一分，别人少做一个特征就不落入范围。
- 少写必要特征则可能不符合细则第二十三条第二款「从整体上反映技术方案、记载解决技术问题的
  必要技术特征」。
- **上位概括不能过头**：过宽的主要后果是**专利法第二十六条第四款「得不到说明书支持」**，
  而不是笼统的「落入公知常识」。也就是说——**上位与说明书的公开程度是一对约束**，
  你上位到什么程度，说明书就得支撑到什么程度。

**功能性限定是把双刃剑：审查宽、侵权窄。**

- 审查阶段：功能性限定被解释为覆盖所有能实现该功能的实施方式。
- 维权阶段：会被限缩到说明书里记载的**不可缺少的技术特征**＋等同。
- ⇒ **只写功能不写实现，等于把自己的保护范围交给法院去裁量。** 说明书里必须给出足够多样
  的具体实现。

**从属权利要求：层层布防。**

- 每条从属应是**可独立存活的退守阵地**——独权被无效掉时能顶上且仍有价值。
- 覆盖实施例的变体：不同数据源、不同触发条件、不同部署形态、不同步骤顺序。
- 不要把所有特征堆在同一条从属里，否则退守时一次退到底。

> **实务经验，非法条**：网上流传「从属权利要求之间应有明显区别、不宜堆砌彼此接近的」，
> 在现行《专利法实施细则》中检索不到「明显区别」的表述。细则第二十三条第三款只规定
> 「从属权利要求应当用附加的技术特征，对引用的权利要求作进一步限定」，不含「彼此应有明显区别」。
> 所以可以遵循这条经验，但**不要当成法定硬要求引用**。

**不确定用语要谨慎。** 权利要求中出现含义不确定的表述会触及「清楚」要求
（专利法第二十六条第四款）。实务中被列为风险较高的包括「约」「等」「类似物」这类表述，
除非本领域有公认含义。**「优选」本身不是法定禁用语**，但它在权利要求中通常缺乏限定作用，
写了要清楚它不产生保护范围。

**授权后注意「捐献原则」**（最高人民法院司法解释一第五条）：
**仅在说明书或附图中描述、而未记载在权利要求中的技术方案，维权时法院不予支持。**
⇒ 说明书与权利要求是**互补而非替代**——说明书写得再全，没进权利要求就捐给了公众。

## 3. 说明书

**充分公开是硬门槛**（专利法第二十六条第三款）：应达到**所属技术领域的技术人员能够实现**的程度。
这与权利要求写得如何无关，是独立的驳回理由。

- **背景技术写足**。它决定「技术问题」是什么，而创造性判断以「实际解决的技术问题」为起点。
  只写「现有技术存在不足」是浪费。
- **发明内容与权利要求对齐**：权利要求里每个技术特征，说明书都要有明确记载和支撑。
- **具体实施方式给到可复现程度**：数据来源、参数取值范围、边界条件、异常处理。
- **有益效果**要与可核对的证据对齐。

**充分公开是双向的**：写少了不满足 26.3；写多了若没进权利要求，按捐献原则拿不回来。
**说明书写多宽，权利要求就要跟着写多宽。**

## 4. 法律后果级的硬规则

**① 公开的时序——中国没有覆盖论文发表的宽限期。**
专利法第二十四条只列四项、六个月：紧急状态下的公共利益首次公开、中国政府主办或承认的国际展览会
首次展出、**规定的**学术会议或技术会议首次发表、他人未经同意泄露。

**论文、arXiv、学位论文、普通学术会议、产品发布、公开演示，都不在这四项里。**
「规定的学术会议」还被进一步限缩到我局认可的会议——省以下、受托召开、借名召开的都不算。

**宽限期 ≠ 优先权**：它不改变申请日，公开后他人独立作出的在先申请仍可能把你挡死。

⇒ **先申请，后公开。**手上有待发表的论文或待发布的系统，先确认申请日。

**② 诚实信用是法定依据**（细则第十一条，2024 年新增）：它被**初审、驳回、无效三处**援引
（细则第五十条、第五十九条、第六十九条）。
**编造实施例、实验数据，不只是道德问题，是会直接导致驳回或授权后被宣告无效的法律问题。**

**③ 软件走发明专利，不能走实用新型。** 计算机程序本身属于智力活动的规则和方法
（专利法第二十五条），且实用新型必须是有形状构造的产品并须有附图。
纯软件方案只能申请发明专利。

**④ 数据与用途的合法性——两件事不要混。**

- **遗传资源**：违反法律、行政法规的规定**获取或利用遗传资源**，并依赖该遗传资源完成的发明创造，
  依**专利法第五条第二款**不授予专利权。这是独立的法定不授权事由。
- **其他数据**：违法采集或违法使用数据，**不当然导致方案不可专利**。细则第十条规定第五条第一款
  「不包括仅其实施为法律所禁止的发明创造」；审查指南 3.1.1 紧接着写明「由于其被滥用而违反法律的，
  则不属此列」，并举例：**武器的生产销售受法律限制，但武器本身及其制造方法仍属可授权客体**。
  ⇒ 照此逻辑，数据来源违法属**实施受限**，是合规问题（可能影响实施与维权），**不是**第五条第一款的
  驳回理由——**注意这一步是指南逻辑的延伸，指南未直接就「数据」表态**。
  不要因为数据来源有瑕疵就放弃申请——先把方案本身的可专利性问清楚。

## 5. 常见失败模式

| 症状 | 后果 | 改法 |
|---|---|---|
| 独权写成实施例的原样 | 保护范围窄，容易绕开 | 抽取必要特征，其它下沉到从属 |
| 功能写得宽、实现写得少 | 维权时被限缩到说明书那一点 | 补足具体实现，或收窄功能表述 |
| 说明书写得像汇报，只讲结论 | 不满足 26.3，驳回 | 补可复现的实施细节 |
| 只在说明书里写了却漏进权利要求 | 按捐献原则拿不回来 | 回查权利要求是否覆盖说明书的每个变体 |
| 只写「解决了 X 问题」 | 创造性论证无依据 | 补技术手段与作用机理 |
| 定稿晚于论文／发布会 | 自己公开导致丧失新颖性 | 先申请后披露 |
| 从属全是同一条主线的细分 | 独权失效后无可退守 | 补不同维度的变体 |

## 6. 交付前自检

- [ ] 独权的必要技术特征是否**恰好**（不少、也不多）？
- [ ] 每条从属单独拿出来，是否仍是一个有价值的技术方案？
- [ ] 说明书里描述的每个变体，权利要求是否都覆盖了？（捐献原则）
- [ ] 功能性限定是否配了足够多样的具体实现？
- [ ] 说明书的每个实施例，改天（非本团队）能否照着重做出来？
- [ ] 申请日是否早于任何形式的对外公开（含论文、arXiv、演示）？
- [ ] 实施例中的数据是否真实？有无披露限制？
