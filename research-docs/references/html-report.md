# HTML 汇报页 / md 与 html 同版放映件

读者**自行浏览**（无人讲解），或事后回看。与 PPT 的差别：没有口头层兜底，
所以**可见层必须自足**——每一屏都要能独立读懂；但也因此更容易信息过载。

## 1. 判据

**没有讲者 = 没有口播层。** PPT 里靠讲出来的过程、术语解释，在这里要么上屏、要么进折叠块/
附录页。不能靠「读者自己猜」。

**同版两份必须同源。** 若同时维护 `*.md`（源）与 `*.html`（放映版），
**改动其一必须同步另一**，否则两份会对同一事物给出不同说法。
建议在文件头互相声明「本文件与 X 同版，改动须同步」。

**不写易腐数字。** 规模类、计数类数字一律**指向权威源**（生成物文件、脚本输出、连库命令），
正文不复制快照。若必须写，标明「截至 YYYY-MM-DD 的快照，不作现状引用」。

## 2. 结构

- **单页滚动优于分页**（除非明确要当演示用）。浏览者需要能搜、能定位、能一次看完。
- **首屏给结论**：标题 → 一句话主张 → 3–4 条支撑 → 详细内容。向下滚动逐层展开。
- **一屏一个论点**。屏幕高度是硬约束，长段落要拆。
- **导航**：章节锚点、返回顶部。超过 6 屏就需要目录。
- **折叠块（`<details>`）放细节**：口径说明、复跑命令、弃用口径、待办——
  这些是「需要时能查到」而非「必须看见」的信息。

## 3. 视觉

- **沿用项目既有的翻页框架与视觉体系**，不要每次新造一套。仓库里已有放映件时，
  复用它的字体、间距、配色与翻页逻辑。
- **对比度用屏幕标准**，但投影场景仍按 ≥4.5:1 取（浏览者可能投屏）。
- **表格在窄屏会溢出**，要么转成卡片式堆叠，要么允许横向滚动并给出提示。
- **深色主题**适合放映，但打印/截图时反色。若材料会被截图引用，优先浅色或提供切换。

## 4. 交互原型的特别提醒

手写的交互原型（网状图、链路展示）**通常没有 md 源**，改起来比看起来贵：
结构会随上游事实源变化而滞后。在文件头写明「建档时快照，以 X 为准」，
并在 README 里登记它的权威源——避免日后被当成现状引用。

## 5. 交付前自检

- [ ] 任意截取一屏，能否独立读懂？
- [ ] 有没有该进折叠块的细节留在正文里？
- [ ] 规模/计数类数字是否指向了权威源，而不是复制的快照？
- [ ] md 与 html 是否同版？文件头有没有声明同步关系？
- [ ] 窄屏下表格是否溢出？
- [ ] 是否复用了仓库既有框架，而不是新造视觉？

> **审查怎么执行**见 `review-protocol.md`；本体裁的「实测」形态是渲染后逐屏目视（含窄屏）。
