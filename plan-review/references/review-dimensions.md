# 审查维度与规则清单

本文件是 `plan-review` 审查子 agent 的核对基准。每条规则标注严重级别（blocker / major / minor），级别含义见 `blocking-criteria.md`。

---

## SCP：目标与范围

- **SCP-001**（blocker）：计划无明确目标、目标本身有误（方向性错误），或成功标准无法客观判定。审查者无法回答「做到什么程度算完成」
  > 目标必须可被第三方客观衡量；「把性能做好」类目标不可判定，需落到「P99 延迟 < 10ms」级别。
- **SCP-002**（blocker）：范围边界缺失或模糊，无法确定哪些内容在计划内/外
  > 无范围边界的计划会无限膨胀，或遗漏关键部分而自认为覆盖。
- **SCP-003**（major）：目标与范围存在歧义，可通过澄清解决但当前未澄清
- **SCP-004**（minor）：多个目标混杂未拆分，或表述冗余

## FEAS：正确性与可行性

- **FEAS-001**（blocker）：方案依赖的假设与技术事实矛盾，或存在已知反例
  > 例：假设某 API 线程安全但文档明确非线程安全；假设某库跨平台但仅支持 Linux。
- **FEAS-002**（blocker）：核心步骤技术上不可行——无已知实现路径，或违反平台/语言约束
- **FEAS-003**（major）：方案正确但依赖未经验证的新技术/新库，且风险未标注
- **FEAS-004**（major）：方案在边界条件下不成立（并发、大数据量、极端输入）
- **FEAS-005**（minor）：方案正确但存在可简化的冗余

## COMP：完整性

- **COMP-001**（blocker）：关键实施步骤缺失，导致计划无法落地
  > 「关键」指缺失后整个计划无法推进或交付物无法形成。
- **COMP-002**（blocker）：计划内部步骤存在矛盾（前后条件冲突、产物不衔接）
- **COMP-003**（major）：遗漏边界/异常/回滚路径（失败时如何清理、如何回退）
- **COMP-004**（major）：遗漏必要的非功能需求（安全、性能、可维护性、可观测性）
- **COMP-005**（minor）：步骤描述过粗，细节留白但方向正确

## RISK：风险与缓解

- **RISK-001**（blocker）：核心路径存在不可接受且无缓解措施的风险
- **RISK-002**（major）：高概率风险未提供缓解措施
- **RISK-003**（major）：单点失败（SPOF）未识别——关键环节无冗余/无备选
- **RISK-004**（minor）：风险已识别但缓解措施过于笼统

## DEP：依赖与顺序

- **DEP-001**（blocker）：任务顺序存在硬性依赖倒置——后置任务被当作前置依赖
  > 例：先写「集成测试」再写「被测模块」，先发布再迁移数据。
- **DEP-002**（major）：外部依赖未识别（第三方库、环境、权限、数据、人力）
- **DEP-003**（major）：关键路径未标注，或关键路径估算与实际明显不符
- **DEP-004**（minor）：可并行任务被串行排布，拖长周期

## VERIF：可验证性

- **VERIF-001**（blocker）：验收标准不可客观验证——主观或无法测量，无法判断是否完成
  > 与 SCP-001 的分界：SCP-001 管**整体目标**层（计划要达到什么），VERIF-001 管**阶段验收**层（每个阶段产出如何验证）。同一缺陷只挂一条，避免双计。
- **VERIF-002**（major）：阶段产物/验收标准缺失，无法判断某阶段是否完成
- **VERIF-003**（minor）：验收标准存在但不够具体（缺量化指标）

## RES：工作量与资源

- **RES-001**（major）：工作量估算明显低估/高估（如 2 倍以上）
- **RES-002**（minor）：人力/资源分配未说明
- **RES-003**（minor）：未预留缓冲时间，未考虑依赖阻塞导致的延期
