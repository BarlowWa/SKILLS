# 阻塞判定标准

本文件定义 `plan-review` 三级严重级别的判定口径，供审查子 agent 分级时参照，避免凭感觉分级。

---

## blocker（阻塞，强制修订后复审）

判定标准：**满足任一即判 blocker**——

1. **方向性错误**：计划指向的目标本身有误，或方案路线根本走不通。
2. **技术不可行**：核心步骤无已知实现路径，或违反平台/语言硬约束。
3. **关键步骤缺失**：缺失后计划无法落地、交付物无法形成。
4. **内部矛盾**：计划内步骤前后冲突，产物不衔接。
5. **验收不可判定**：成功标准主观或不可测量，无法客观判断是否完成。
6. **依赖倒置**：任务顺序存在硬性依赖倒置，无法按序执行。
7. **范围边界缺失**：无法确定哪些内容在计划内/外，无法判断是否覆盖或越界。
8. **不可接受风险无缓解**：核心路径存在不可接受且无缓解措施的风险。

**特征**：不是「做得不够好」，而是「**照此执行无法完成或必错**」。blocker 必须先修订计划，再复审确认。

## major（重大，仅记录，不强制复审）

判定标准：计划**可执行**，但存在会导致**返工或重大风险**的缺陷——

1. 方案正确但依赖未验证的新技术，风险未标注。
2. 遗漏异常/回滚/非功能需求路径。
3. 高概率风险无缓解措施，或存在单点失败。
4. 外部依赖未识别，或关键路径估算明显不符。
5. 阶段产物/验收标准缺失（但整体目标仍可判定）。
6. 工作量估算明显偏差（如 2 倍以上）。
7. 目标与范围存在歧义——可通过澄清解决，但当前未澄清（SCP-003）。
8. 方案在边界条件下不成立——并发、大数据量、极端输入下失效，但正常路径可行（FEAS-004）。
9. 需求不健全——目标与所陈述的需求方向性不符（目标达成了，需求所述问题依然存在）（SCP-005）。
10. 承载核心结论的外部前提未标注核验方式，且不涉及新技术/新库（FEAS-006）。

**特征**：「照此执行能做完，但很可能返工、延期或埋雷」。终审前应处理或显式记录。

## minor（优化建议，仅记录）

判定标准：不影响执行与交付，仅影响**效率或质量**——

1. 方案冗余可简化。
2. 可并行任务被串行排布。
3. 验收标准不够具体但存在。
4. 人力分配/缓冲时间未说明（仅限多人协作/外包场景，见 RES-002 / RES-003 的门控）。
5. 目标表述冗余、步骤描述过粗。
6. 风险已识别但缓解措施过于笼统。

**特征**：「做了更好，不做也能交」。

## 分级时的边界判断（易混淆场景）

| 场景 | 级别 | 理由 |
|------|------|------|
| 方案有已知反例 | blocker | 照做必错，FEAS-001 |
| 方案依赖新技术但未验证 | major | 可能可行，风险需标注，FEAS-003 |
| 漏写「回滚步骤」 | major | 计划仍可执行，COMP-003 |
| 漏写「核心实现步骤」 | blocker | 无法落地，COMP-001 |
| 验收标准主观（整体或阶段） | blocker | 无法判断是否完成，VERIF-001（整体目标层则记 SCP-001） |
| 验收标准缺量化但可判断 | minor | 能判断，不够精确，VERIF-003 |
| 工作量低估 2 倍 | major | 明显偏差（2 倍以上），RES-001 |
| 工作量低估 30% | minor | 不阻塞；**仅当涉及多人协作/外部依赖方时**记入 RES-003（缓冲不足） |
| 整体目标主观 | blocker | 无法判断方向，SCP-001 |
| 目标/范围含混但可澄清 | major | 尚未澄清，SCP-003 |
| 正常路径可行、边界条件失效 | major | 仍能交付，FEAS-004 |
| 边界/异常路径**完全未提及** | major | 计划仍可执行，COMP-003 |
| 并发/极端输入下**必错** | blocker | 照做必错，FEAS-002 |
| 目标清晰、但指错了要解决的问题 | major | 计划内部可判定，SCP-005 |
| 目标缺失或不可判定（含未说明要解决什么） | blocker | 根缺陷，只挂 SCP-001 |
| 需求本身就是错的（与需求方原意相悖） | 本技能不判 | 需计划外证据，转 `deep-research` |
| 核心结论依赖未核验的外部前提（非新技术） | major | 不成立则方案不成立，FEAS-006 |
| 仅影响局部判断的外部前提未标注 | minor | 同上，影响面小 |

> 拿不准时**从宽**（倾向标 major 而非 blocker），避免误判导致无效复审循环；但「照做必错」与「无法落地」两类场景必须坚决标 blocker。
