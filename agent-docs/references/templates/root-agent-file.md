# 根指令文件模板（CLAUDE.md / AGENTS.md）

> **用法**：复制下方骨架，替换占位符。目标 ≤150 行；写完后逐条问
> 「删掉这句，agent 会犯错吗？」。
>
> **不要放**：变更日志、时点实测（"2026-xx-xx 实测"）、易变计数、逐文件说明、
> 代码可推断的通用规范、gitignore 路径里的判据。

---

````markdown
# <项目名>

<一句话定位：是什么、给谁用。>

## 项目地图

| 模块 | 说明 |
|------|------|
| [<模块>](<路径>/) | <职责> |

<依赖关系一句话：谁依赖谁、哪些是基础设施层。>

## 硬规则

<!-- 只写"删掉就会犯错"的条目；每条尽量可验证。 -->

- <规则一（如：修 bug 先红后绿）>
- <规则二（如：不自动提交，提交走 /git-commit）>
- <规则三（如：判定构建通过看重建行，不看退出码）>

## 常用命令

```bash
# 构建
<command>
# 测试（日常）
<command>
# 测试（含已知红灯）
<command>
```

> 计数与口径随配置变，引用时跑命令现数，不要写死数字。

## 路由

<!-- 改到哪里 → 先读哪个文件。避免 agent 误读无关子项目规则。 -->

- 改 `<目录>` → 先读 `<路径>/CLAUDE.md`
- 测试口径 / 排障 → `docs/testing/`
- 方案取舍与「为什么不用 X」→ `docs/decisions/`
- 面向人的用法 → `docs/guides/`
````

## 骨架外的提醒

- **子目录文件只写差异**：根文件已有的规则不要在 `tools/<module>/CLAUDE.md` 里复制。
- **必须每次都发生的事**不要只写成文字：配 hook / CI。
- **跨工具**：若还要给 Codex/Cursor 用，根文件改名 `AGENTS.md`，
  `CLAUDE.md` 只留一行 `@AGENTS.md`；不要维护两份。
