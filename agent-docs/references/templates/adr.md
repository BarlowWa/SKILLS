# ADR 模板

> **用法**：`docs/decisions/NNNN-<slug>.md`，编号递增。
> **状态被推翻时不要删原文**——改状态为「已推翻」，并链到取代它的 ADR；
> 结论可被推翻，但推翻记录本身是决策史的一部分。

---

```markdown
# NNNN. <决策标题>

- **状态**：提议 / 已接受 / 已推翻（被 NNNN 取代）
- **日期**：YYYY-MM-DD
- **Owner**：<负责复核的人>
- **依据**：<工单 / 讨论链接 / 实测记录 / 调研文档>

## 背景

<要解决什么问题；约束条件（环境、平台、已有代码）。>

## 决策

<决定做什么。一句话能说清就一句话。>

## 考虑过的方案

| 方案 | 结论 | 理由 |
|------|------|------|
| <方案 A> | ✅ 采用 | <理由> |
| <方案 B> | ❌ 否决 | <为什么不选——这条最重要，防止日后重提> |

## 后果

- **正面**：<得到什么>
- **代价**：<放弃什么、需要维护什么>
- **风险**：<已知风险与缓解>

## 复核

- **下次复核日期**：YYYY-MM-DD
- **失效信号**：<出现什么情况说明该决策不再成立>
```

## 写法要点

- **「否决理由」是 ADR 的核心价值**：没有它，同一个方案会被反复重提。
- 数字和外部事实带日期与来源；决策理由本身不需要频繁更新。
- ADR 入库（不是 `.claude/plans/`）——它是持久契约，换机/克隆后仍要可读。
